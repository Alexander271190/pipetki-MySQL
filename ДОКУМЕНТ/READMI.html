README — Система учёта оборудования КДЛ

Версия: 3.2.0
Стек: Node.js 20 + Express 4 + MySQL 8 + Vanilla JS + Nginx
Деплой: Docker Compose (4 контейнера)
Дата: 19.10.2026

Назначение: веб-приложение для учёта лабораторного оборудования и контроля сроков поверки. Работает в браузере, данные — на сервере лаборатории.

3. Бэкенд — модули

3.1. Точка входа — server.js

  • Настройка Express (json limit 50mb, static frontend/)
  • wrapRouter() — оборачивает async-обработчики в asyncHandler
  • Подключение 13 роутов: /api/auth, /api/pipettes, /api/users, /api/settings, /api/log, /api/import, /api/export, /api/barcodes, /api/barcode-printers, /api/help, /api/view-templates, /api/equipment-templates
  • GET /api/health — healthcheck
  • Старт: ждёт MySQL (90 попыток × 2 сек = 3 мин), затем initSchema() + seedInitialData(), потом app.listen(3000)
  • Если БД не поднялась — фоновый интервал (5 сек) догоняет
  • Запускает utils/cleanup.js → startCleanupScheduler() — очистка audit_log старше AUDIT_LOG_RETENTION_DAYS

3.2. Слой БД — db/

ФайлЧто делает
pool.jsПул соединений MySQL (10 соединений, utf8mb4, TZ UTC). Обёртка getConnection() трекает SET FOREIGN_KEY_CHECKS = 0/1 и гарантирует, что соединение вернётся в пул с FK_CHECKS = 1 (или будет destroy() при сбое). Экспортирует pool, query(), getConnection(), safeParse()
schema.jsinitSchema() — CREATE TABLE IF NOT EXISTS для 15 таблиц + ensureColumns() + ensureIndexes(). Идемпотентно
seed.jsseedInitialData() — admin (без пароля), 8 отделов, 6 типов, 16 полей, 8 фильтров, 5 демо-приборов (флаг demo_seeded). generatePipetteId(prefix, conn) — с FOR UPDATE. seedHelpDocs(conn)
index.jsРеэкспорт всех функций из pool.js, schema.js, seed.js под общим именем db

3.3. Middleware

ФайлЧто
auth.jsauthenticate — проверяет JWT, подгружает user, проверяет password_changed_at > iat + 2, обрабатывает impersonate. requireRole(['admin']), requirePermission('edit_pipette'), requireAnyPermission(['a','b']). Парсит user.extra_permissions один раз → req.user._perms. Если must_set_password или must_change_password — блокирует всё, кроме роутов с флагом req.allowWhenPasswordMustChange
passwordPolicy.jsvalidatePassword() — 8+, a-z, A-Z, 0-9, спецсимвол, без пробелов
validate.jsvalidateISODate(), normalizeInterval(), todayLocalStr()

3.4. Утилиты — utils/

ФайлЧто
db-helper.jswithTransaction(fn) — единая обёртка: getConnection → beginTransaction → fn(conn) → commit, при ошибке rollback, всегда release
audit.jslogAction(req, action, details, conn?) — единая запись в audit_log. Ошибки не бросает (только console.error)
cleanup.jsstartCleanupScheduler() — первый запуск через 60 сек, потом раз в 24 ч. cleanupAuditLog() — DELETE старше N дней. N = AUDIT_LOG_RETENTION_DAYS (default 90)
equipment-types.jsКэш типов (TTL 60 сек). getEquipmentTypes(), getPrefix(type), getDefaultInterval(type), isExternal(type), invalidateCache()

ℹ️ Дедубликация: все пипетки-роуты (crud.js, bulk.js, calibration.js, transfers.js) используют:
  • withTransaction — вместо db.getConnection + beginTransaction/commit/rollback/release
  • logAction — вместо INSERT INTO audit_log (после коммита)
  • findPipetteOrFail(conn, id, user, { forUpdate }) — вместо инлайн SELECT + 404/403
  • canAccessDepartment — только в bulk-циклах (пропуск + skipped.push, не 403 на всю операцию)

🎯 Резюме
Проект — классический Express + MySQL + Vanilla JS SPA. 13 роутов, 20 JS-модулей, 8 CSS-модулей, 15 таблиц БД. Всё модульное, изолированное. Единые хелперы: withTransaction (транзакции), logAction (аудит), findPipetteOrFail (поиск с доступом), buildDepartmentScope (скоуп по отделу), sqlComputedStatus (единственный источник статусов). Корзина не реализована (удаление физическое с двойным подтверждением). Блоки-подсказки — через UI.infoBlock/warningBlock/successBlock/dangerBlock.
