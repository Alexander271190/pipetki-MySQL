README — Система учёта оборудования КДЛ

Версия: 4.0.1 (Vue 3)
Стек: Node.js 20 + Express 4 + MySQL 8 + Vue 3 + TypeScript + Vite + Pinia + Nginx
Деплой: Docker Compose (4 контейнера)
Дата: 11.11.2026

Назначение: веб-приложение для учёта лабораторного оборудования и контроля сроков поверки. Работает в браузере, данные — на сервере лаборатории.
🔄 Миграция: фронтенд переписан с Vanilla JS (20 файлов) на Vue 3 + TypeScript + Vite. Бэкенд не менялся — все API-контракты, БД, схемы, роуты остались те же. Совместимость 100%.

4. Фронтенд — Vue 3

4.1. Принципы архитектуры

✅ Слои Vue-приложения:
  1. API (src/api/*.ts) — тонкие обёртки над apiRequest(). Только HTTP. Никакой логики.
  2. Stores (src/stores/*.ts) — Pinia. Глобальное состояние + actions. Единственное место, где хранятся данные.
  3. Composables (src/composables/*.ts) — переиспользуемая логика. Например, useModals — открытие модалок с проверками прав.
  4. Components (src/components/**/*.vue) — только рендеринг + локальное состояние. Не лезут в fetch напрямую — только через api/ или stores/.
  5. Views (src/views/*.vue) — страницы, привязанные к роутам.

4.5. Реактивность и потоки данных

┌─────────────────────────────────────────────────────────────┐
│ Пользователь нажимает кнопку                                 │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Компонент вызывает действие:                                 │
│  - через useModals() (с проверкой прав)                     │
│  - или напрямую через store                                  │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Store action (Pinia):                                        │
│  - вызывает API (api/pipettes.ts, ...)                      │
│  - обновляет reactive state                                  │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Vue автоматически перерисовывает:                            │
│  - computed в компонентах                                   │
│  - v-for, v-if, интерполяции                                │
└─────────────────────────────────────────────────────────────┘
⚠️ Правила:
  • Никогда не вызывать fetch из компонентов напрямую (кроме миграции/скачивания файлов)
  • Все изменения данных — через actions сторов
  • Все запросы — через src/api/*.ts (кроме downloadFile, там свой fetch для стриминга)
  • Модалки открываются только через ui.open('name', data)
  • Проверки прав — perm.canXxx.value (computed из usePermissions)

9.4. Известные проблемы / TODO

🐛 BUG: при тёмной теме в шапке плохо видны элементы
Симптом: при переключении на тёмную тему кнопки «Пароль», «Выйти», «Вернуться» (impersonate), а также текст .user-info .name / .position — могут быть плохо различимы (белый текст на светлом фоне или наоборот).

Причина: в _dark.css правила для html[data-theme="dark"] .header меняют фон на тёмно-синий, но кнопки и текст внутри .user-info используют CSS-переменные --text / --text-strong, которые при тёмной теме становятся светлыми — а .user-info имеет свой полупрозрачный белый фон rgba(255,255,255,.1), из-за чего светлый текст на светлом фоне не читается.

Где чинить:
  • src/styles/css/_dark.css → секция «ТЁМНАЯ ТЕМА» → .header, .user-info, .user-info .btn
  • Либо src/components/layout/AppHeader.vue — если используются inline-стили
Фикс (примерный): 
/* _dark.css */
html[data-theme="dark"] .user-info {
  background: rgba(255,255,255,.08);
  color: #e2e8f0;
}
html[data-theme="dark"] .user-info .btn {
  color: #e2e8f0 !important;
  border-color: rgba(255,255,255,.3) !important;
  background: rgba(255,255,255,.15);
}
html[data-theme="dark"] .user-info .btn:hover {
  background: rgba(255,255,255,.25);
}
html[data-theme="dark"] .user-info .name { color: #f1f5f9; }
html[data-theme="dark"] .user-info .position { color: #cbd5e1; }
