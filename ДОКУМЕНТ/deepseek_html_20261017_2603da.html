Обновление системы

sudo apt update

sudo apt install -y \
  curl \
  wget \
  git \
  ca-certificates \
  gnupg \
  lsb-release \
  ufw \
  htop \
  nano

Настройка firewall (UFW)

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp

sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status

sudo adduser deploy
sudo usermod -aG sudo deploy

su - deploy

3. Установка Docker

Официальный скрипт (быстро)

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

Проверка

docker --version
# Docker version 24.x.x

docker compose version
# Docker Compose version v2.x.x
⚠️ После usermod — выйдите и войдите в сессию заново, чтобы применились права на docker.

Автозапуск Docker

sudo systemctl enable docker
sudo systemctl start docker
sudo systemctl status docker

5. Настройка .env

Копирование шаблона

cp .env.example .env

Генерация JWT_SECRET

🔴 КРИТИЧНО: замените JWT_SECRET на случайные 64 hex-символа. Не используйте дефолтное значение «change_this_secret_key»! 
openssl rand -hex 32

Редактирование .env

nano .env

Пример:

PORT=3000
DB_HOST=db
DB_PORT=3306
DB_NAME=pipette
DB_USER=pipette
DB_PASSWORD=YourStrongPassword2026!
JWT_SECRET=a1b2c3d4e5f6... (64 символа)

Пароль БД

Замените и в .env, и в docker-compose.yaml (в двух местах: MYSQL_PASSWORD и MYSQL_ROOT_PASSWORD).

⚠️ Не забудьте: если меняете пароль после первого запуска БД — потребуется сброс тома (docker compose down -v), иначе MySQL не примет новый пароль.

6. Первичный SSL (Let's Encrypt)

Приложение работает через HTTPS. Сертификаты получаются автоматически через certbot. Первый раз — вручную.

Вариант A: есть домен (рекомендуется)

  1. Направьте A-запись домена (например, pipette.example.ru) на IP сервера
  2. Дождитесь DNS-распространения (ping pipette.example.ru — должен вернуть IP)
  3. В nginx/pipette.conf замените IP на домен: 
    server_name pipette.example.ru;

Вариант B: только IP (как у вас)

Используется server_name 5.189.243.15; — уже настроено.

Получение сертификата (первый раз)

cd /opt/pipette-app

# 1. Запустить nginx (без app — для ACME challenge)
docker compose up -d nginx

# 2. Получить сертификат
docker compose run --rm certbot certonly \
  --webroot \
  --webroot-path /var/www/certbot \
  --email admin@example.ru \
  --agree-tos \
  --no-eff-email \
  -d 5.189.243.15
  # (для домена: -d pipette.example.ru)

# 3. Перезапустить nginx
docker compose restart nginx

Проверка

docker compose logs certbot --tail 20
# Должно быть: Certificate saved at /etc/letsencrypt/live/...
ℹ️ Автообновление: certbot-контейнер сам обновляет сертификаты каждые 12 часов и посылает HUP nginx. Вмешательство не нужно.

7. Запуск (docker compose up)

Сборка и запуск

cd /opt/pipette-app
docker compose up -d --build
ℹ️ Первый запуск занимает 60–180 сек (сборка Node + инициализация MySQL). Не пугайтесь паузы.

Проверка запуска

# Все 5 контейнеров
docker compose ps

# Ожидаемо:
# NAME              STATUS
# pipette_app       Up (healthy)
# pipette_db        Up (healthy)
# pipette_nginx     Up (healthy)
# pipette_certbot   Up

Логи приложения

docker logs pipette_app --tail 30

Ожидаемо:

📝 logger-bootstrap.js активен — логи пишутся в /app/logs
✅ MySQL подключён
✅ Схема БД готова
🚀 Server on http://0.0.0.0:3000
🔴 Если в логах:
• MySQL не ответил за 3 минуты — БД не поднялась, проверьте docker logs pipette_db
• SyntaxError — синтаксическая ошибка в коде, проверьте файлы
• EADDRINUSE — порт 3000 занят

8. Первый вход

  1. Откройте https://<host>
  2. Логин: admin, пароль: пустой
  3. Система покажет окно «Установка пароля администратора»
  4. Введите пароль: 8+, a-z, A-Z, 0-9, спецсимвол
  5. Сохраните — войдёте в систему
⚠️ Если пишет «Неверный логин или пароль» при пустом пароле — значит, seed не отработал. Проверьте логи docker logs pipette_app | grep seed. Если БД инициализирована неправильно — docker compose down -v + up -d для полного сброса.

Первичная настройка (10 минут)

  1. Настройки → Пользователи — создать остальных сотрудников
  2. Настройки → Отделы — проверить список
  3. Настройки → Типы оборудования — проверить типы, префиксы, место поверки
  4. Настройки → Поля формы — включить/выключить нужные
  5. Настройки → Принтеры этикеток — добавить принтеры
  6. Настройки → Общие — порог warn_days (по умолчанию 30)

10. Обновление

Вариант A: обновление кода (без пересборки)

Если изменились только routes/, frontend/, db/ и т.п. — volume mount подхватит изменения:

cd /opt/pipette-app

# 1. Скачать обновления
git pull origin main
# или распаковать архив поверх

# 2. Перезапустить app
docker restart pipette_app

# 3. Проверить логи
docker logs pipette_app --tail 20
✅ Быстро (5 секунд): код подхватывается без пересборки образа, благодаря volume mount.

Вариант B: обновление с пересборкой

Если изменились package.json, Dockerfile, docker-compose.yaml:

cd /opt/pipette-app
git pull origin main
docker compose up -d --build app
docker logs pipette_app --tail 20

Откат

# Если что-то пошло не так
git log --oneline -5           # найти нужный коммит
git checkout <commit-hash>
docker compose up -d --build app

11. Резервное копирование

Что бэкапить

ЧтоГдеРазмерЧастота
БД MySQLmysqldata/ или через mysqldump~10–100 МБЕжедневно
SSL-сертификатыdata/certbot/~50 КБПри обновлении
Загруженные картинкиfrontend/uploads/~5–50 МБЕженедельно
Конфигурация.env, docker-compose.yaml, nginx/< 10 КБПри изменении

Бэкап БД через mysqldump (рекомендуется)

# Создать папку для бэкапов
mkdir -p /opt/backups/pipette
cd /opt/backups/pipette

# Сделать бэкап
docker exec pipette_db mysqldump \
  -u pipette \
  -pSeno16/1978S \
  --single-transaction \
  --routines \
  --triggers \
  pipette > pipette_$(date +%Y-%m-%d_%H-%M).sql

# Размер
ls -lh

Автоматизация (cron)

sudo nano /etc/cron.d/pipette-backup
# Ежедневно в 3:00 — бэкап БД
0 3 * * * root docker exec pipette_db mysqldump -u pipette -pSeno16/1978S --single-transaction pipette | gzip > /opt/backups/pipette/pipette_$(date +\%Y-\%m-\%d).sql.gz

# Еженедельно — удалять бэкапы старше 30 дней
0 4 * * 0 root find /opt/backups/pipette -name "*.sql.gz" -mtime +30 -delete
⚠️ Пароль в cron — виден в ps aux. Если критично — используйте ~/.my.cnf с паролем.

Бэкап картинок и конфигурации

cd /opt/pipette-app
tar -czf /opt/backups/pipette/uploads_$(date +%Y-%m-%d).tar.gz frontend/uploads/
tar -czf /opt/backups/pipette/config_$(date +%Y-%m-%d).tar.gz .env docker-compose.yaml nginx/

12. Восстановление

Из SQL-дампа

cd /opt/backups/pipette

# 1. Остановить app (чтобы не было записи в БД)
docker compose stop app

# 2. Восстановить БД
docker exec -i pipette_db mysql -u pipette -pSeno16/1978S pipette < pipette_2026-10-18.sql

# 3. Запустить app
docker compose start app

# 4. Проверить
docker logs pipette_app --tail 10

Если дамп сжат gzip

gunzip -c pipette_2026-10-18.sql.gz | docker exec -i pipette_db mysql -u pipette -pSeno16/1978S pipette

Полное восстановление (включая volumes)

cd /opt/pipette-app
docker compose down -v       # УДАЛИТ ВСЕ ДАННЫЕ!
# Восстановить из бэкапа
docker compose up -d
docker compose stop app
docker exec -i pipette_db mysql -u pipette -pSeno16/1978S pipette < /opt/backups/...sql
docker compose start app
🔴 ВНИМАНИЕ: docker compose down -v удаляет все volumes — БД, сертификаты, логи. Делайте только если уверены, что есть бэкап.

13. Мониторинг

Просмотр логов

# Логи приложения (последние 100 строк)
docker logs pipette_app --tail 100

# Следить в реальном времени
docker logs pipette_app -f

# Логи БД
docker logs pipette_db --tail 50

# Логи Nginx
docker logs pipette_nginx --tail 50

Логи в файлы (уже настроено)

# Логи пишутся в /opt/pipette-app/logs/
ls -lh logs/

# Читать
tail -f logs/app-$(date +%Y-%m-%d).log

Проверка ресурсов

# Docker stats (CPU, RAM)
docker stats --no-stream

# Место на диске
df -h

# Свободная RAM
free -h

# Размеры volumes
docker system df

Мониторинг healthcheck

# Простой bash-цикл (каждые 60 сек)
while true; do
  status=$(docker inspect -f '{{.State.Health.Status}}' pipette_app)
  echo "$(date): $status"
  sleep 60
done

Внешний мониторинг

Добавьте https://<host>/api/health в:

  • Uptime Robot (бесплатно, 5 мин интервал)
  • Zabbix / Prometheus + Grafana — если есть инфраструктура

docker logs pipette_app --tail 100
ОшибкаПричинаРешение

Cannot find moduleНе установлены зависимостиdocker compose up -d --build app
EADDRINUSEПорт 3000 занятsudo ss -tulpn | grep 3000 → убить процесс
MySQL не ответилБД не подняласьdocker logs pipette_db
ER_ACCESS_DENIED_ERRORНеверный пароль БДПроверьте .env и docker-compose.yaml

Nginx отдаёт 502 Bad Gateway

# Проверить app
docker ps | grep pipette_app
docker logs pipette_app --tail 20

# Проверить сеть
docker exec pipette_nginx ping -c 2 app

# Перезапустить nginx
docker restart pipette_nginx

SSL-сертификат не обновляется

docker logs pipette_certbot --tail 30

# Принудительное обновление
docker compose run --rm certbot renew --force-renewal
docker compose restart nginx

БД занимает много места

# Размер БД
docker exec pipette_db du -sh /var/lib/mysql

# Очистить audit_log (если > 100000 записей)
docker exec -it pipette_db mysql -u pipette -p
# mysql> USE pipette;
# mysql> DELETE FROM audit_log WHERE timestamp < DATE_SUB(NOW(), INTERVAL 90 DAY);
# mysql> OPTIMIZE TABLE audit_log;

Медленная работа при большом числе записей

# Проверить индексы
docker exec -it pipette_db mysql -u pipette -p
# mysql> USE pipette;
# mysql> SHOW INDEX FROM pipettes;
# mysql> EXPLAIN SELECT * FROM pipettes WHERE department = 'Биохимический';

Если индексов не хватает — они создаются автоматически при старте через ensureIndexes() в db/schema.js.
