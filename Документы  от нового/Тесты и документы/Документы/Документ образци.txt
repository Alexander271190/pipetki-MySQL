1. Введение
1.1. Что это за система
КДЛ-оборудование — веб-приложение для учёта лабораторного оборудования и контроля сроков его поверки. Система ведёт полный жизненный цикл прибора: от поступления в лабораторию до списания.

1.2. Кому предназначено
Лаборанты — повседневная работа: просмотр, поверки, передачи

Старшие лаборанты — расширенные права: добавление, массовые операции

Заведующие — контроль своего отдела

Администратор — полный доступ, настройки (см. отдельное руководство)

1.3. Что можно делать
Просматривать реестр оборудования (с фильтрами, поиском, сортировкой)

Добавлять новые приборы (по одному или партией)

Регистрировать поверки (быстрая и полная история)

Отправлять на поверку и возвращать с неё

Печатать этикетки со штрихкодами

Экспортировать данные в Excel и PDF

Получать напоминания о просроченных поверках

2. Вход в систему
2.1. Открытие системы
Откройте браузер (Chrome, Edge, Firefox, Safari — свежие версии)

Введите адрес системы в адресную строку. Адрес выдаёт администратор.

Откроется экран входа.

📸 [СКРИНШОТ 2.1] Экран входа
Что снять: весь экран логина с фоном (картинка лаборатории), полями «Логин» и «Пароль» и кнопкой «Войти».
Куда вставить: после этого абзаца.

2.2. Первый вход
При первом входе администратор выдаёт вам логин и разовый пароль.

Введите логин

Введите разовый пароль

Нажмите «Войти»

Система сразу попросит сменить пароль — это обязательная процедура

📸 [СКРИНШОТ 2.2] Модалка смены пароля при первом входе
Что снять: модальное окно «Смена пароля» с тремя полями (Текущий, Новый, Подтверждение) и списком требований к паролю.
Куда вставить: после пункта 4.

2.3. Требования к паролю
Пароль должен соответствовать политике, которую настраивает администратор. Стандартные требования:

Минимум 8 символов

Хотя бы одна строчная буква (a-z)

Хотя бы одна заглавная буква (A-Z)

Хотя бы одна цифра (0-9)

Хотя бы один спецсимвол (!@#$%^&* и т.п.)

Без пробелов

Проверка в реальном времени: по мере ввода пароля напротив каждого требования появляется ✅ (выполнено) или ❌ (не выполнено).

2.4. Если забыли пароль
Обратитесь к администратору. Он сбросит пароль и выдаст новый разовый. При следующем входе система снова попросит сменить пароль.

2.5. Выход из системы
Нажмите «Выйти» в правом верхнем углу (рядом с вашим ФИО). Сессия завершится, вы вернётесь на экран входа.

3. Главный экран
После входа открывается главный экран — таблица со всем оборудованием, к которому у вас есть доступ.

📸 [СКРИНШОТ 3.1] Главный экран (полный)
Что снять: весь экран с шапкой, тулбаром, таблицей (5–7 строк) и пагинацией внизу. Если тёмная тема — сделай скриншот в светлой (для документа).
Куда вставить: после этого абзаца.

3.1. Шапка (верхняя панель)
В шапке отображается:

Название системы «Клинико-диагностическая лаборатория учёт оборудования и его поверок»

Кнопка свернуть/развернуть шапку (▲ Свернуть / ▼ Развернуть)

Счётчики:

🟢 В норме — поверка не скоро

🟡 Скоро поверка — в течение N дней (по настройкам)

🔴 Просрочены — срок истёк

Всего — общее количество (при наведении — детальная разбивка)

Ваше ФИО и должность (справа)

Кнопки: вернуться (если вы под другим пользователем), тема, пароль, выйти

📸 [СКРИНШОТ 3.2] Шапка с счётчиками
Что снять: верхнюю часть экрана — заголовок, 4 счётчика (В норме / Скоро / Просрочены / Всего) и правый угол с ФИО и кнопками.
Куда вставить: после списка выше.

3.2. Тулбар (панель действий)
Под шапкой — панель с инструментами:

Поиск — поле для поиска по таблице

Фильтр — кнопка открытия панели фильтров

Сканировать — для сканирования штрихкодов (если есть права)

Ещё ▼ — выпадающее меню с дополнительными действиями

Когда выбраны строки (чекбоксами), появляется панель массовых действий с кнопками «Отправить», «Вернуть», «Ответственный», «Удалить» и «Снять».

📸 [СКРИНШОТ 3.3] Тулбар с выбранными строками
Что снять: тулбар в двух состояниях: (а) без выбора — поиск, фильтр, Ещё; (б) с 2 выбранными строками — появляются кнопки массовых действий. Лучше сделать два скриншота и подписать «до» и «после».
Куда вставить: после списка выше.

3.3. Таблица
Основная часть экрана — таблица с колонками. Стандартный набор:

Колонка	Что показывает
☑	Чекбокс выбора строки
ID	Внутренний номер (например, P-001)
Тип	Пипетка, анализатор, микроскоп и др.
Модель	Название модели + производитель
Объём	Для пипеток (мкл)
Отдел	Где находится
Поверка	Дата последней поверки
Следующая	Дата следующей + сколько дней осталось
Ответственный	Кто отвечает + место хранения
Статус	Бейдж с цветом
Действия	Кнопка ⋮ для меню действий
📸 [СКРИНШОТ 3.4] Таблица с цветными строками
Что снять: 6–8 строк таблицы, где видны разные статусы (зелёные, жёлтые, красные). Убедись, что видны колонки «Следующая», «Статус» и кнопка ⋮.
Куда вставить: после таблицы выше.

3.4. Сортировка
Кликните по заголовку колонки — данные отсортируются по возрастанию (▲). Повторный клик — по убыванию (▼). Третий клик — сброс.

Сортировка работает по: ID, тип, модель, отдел, дата поверки, следующая дата, ответственный, статус.

3.5. Пагинация (внизу)
Внизу таблицы:

«Строк:» — выпадающий список (50 / 100 / 200 / 500 — как настроил админ)

«← Назад» и «Вперёд →» — переход между страницами

«Стр. X из Y» — текущая страница

«Всего: N записей» — общее количество

📸 [СКРИНШОТ 3.5] Пагинация
Что снять: нижнюю полосу с выбором количества строк, кнопками ← Назад / Вперёд → и счётчиком «Всего».
Куда вставить: после списка выше.

3.6. Тёмная и светлая темы
В правом верхнем углу шапки — кнопка 🌙/☀️. Клик переключает тему. Выбор сохраняется между сессиями.

3.7. Свёртывание шапки
Кнопка ▲ Свернуть уменьшает шапку до одной строки — больше места для таблицы. Полезно на маленьких экранах.

📸 [СКРИНШОТ 3.6] Свёрнутая шапка
Что снять: главный экран со свёрнутой шапкой (одна строка с названием и мини-счётчиком).
Куда вставить: после этого абзаца.

В поле «Поиск» введите что угодно:

ID (например, P-001)

Модель (Research Plus)

Серийный номер

Отдел

Ответственного (например, Иванова)

📸 [СКРИНШОТ 4.1] Поиск по «Eppendorf»
Что снять: тулбар с введённым в поиск «Eppendorf» и таблицу ниже, где отфильтрованы только Eppendorf.
Куда вставить: после абзаца выше.

4.2. Фильтры
Кнопка «Фильтр» открывает панель с полями:

Статус — все / в норме / скоро / просрочен / на поверке / брак / в процессе / неактивен

Тип оборудования

Отдел

Ответственный (частичное совпадение)

Модель

Производитель

Дата поверки — период (сегодня / вчера / 7 дней / 30 дней / произвольный)

Внизу панели — кнопки «Сбросить» и «Применить».

📸 [СКРИНШОТ 4.2] Панель фильтров
Что снять: открытую панель фильтра со всеми полями и кнопками внизу.
Куда вставить: после абзаца выше.

4.3. Изменение колонок
Вы можете:

Перетащить колонку — зажмите заголовок и перетащите влево/вправо

Изменить ширину — потяните за правую границу заголовка

Скрыть/показать колонки — через «Настройки → Пользователи → Настроить видимые поля» (только для админа) или личные настройки

Порядок колонок сохраняется автоматически для вашего пользователя.

📸 [СКРИНШОТ 4.3] Перетаскивание колонки
Что снять: момент перетаскивания (заголовок «Модель» с полупрозрачностью над колонкой «Тип», между ними подсветка).
Куда вставить: после абзаца выше.

4.4. Выбор строк
Одна строка — клик по чекбоксу в строке

Несколько — клик по нескольким чекбоксам

Все на странице — чекбокс в заголовке таблицы (выделяет только текущую страницу)

Переход между страницами — выбранные строки сохраняются

В тулбаре появляется индикатор «Выбрано: N».

📸 [СКРИНШОТ 4.4] Выбранные строки
Что снять: 2–3 выбранные строки (с синей подсветкой) и тулбар с надписью «Выбрано: 3».
Куда вставить: после абзаца выше.

5. Действия с одной единицей
Кнопка ⋮ в правой колонке строки открывает меню действий.

📸 [СКРИНШОТ 5.1] Меню ⋮
Что снять: открытое меню действий с пунктами «Быстрая поверка», «Редактировать», «Передать», «История», «Аудит», «Удалить».
Куда вставить: после абзаца выше.

5.1. Быстрая поверка
Когда использовать: когда прибор прошёл поверку и нужно быстро зарегистрировать результат.

Откройте меню ⋮ → «Быстрая поверка»

Введите:

Дата поверки (по умолчанию — сегодня, нельзя указать будущее)

Номер свидетельства (необязательно)

Результат — Годен / Брак / В процессе

Организация (например, ФБУ «Красноярский ЦСМ»)

Примечание (необязательно)

Нажмите «Записать»

Что произойдёт:

Дата последней поверки обновится

В таблице обновится «Следующая»

Статус пересчитается автоматически

📸 [СКРИНШОТ 5.2] Модалка «Быстрая поверка»
Что снять: модалку с заполненными полями (дата — сегодня, свидетельство, результат «Годен»).
Куда вставить: после списка «Что произойдёт».

5.2. Редактировать
Открывает форму редактирования. ID прибора нельзя изменить (он присвоен навсегда).

При смене типа оборудования (например, с пипетки на анализатор) ID автоматически перегенерируется (P-001 → A-001), а история поверок переедет вместе с прибором.

Подробнее — см. раздел 6.2 (создание) — форма редактирования идентична.

5.3. Передать в другой отдел
Используется, когда прибор физически перемещается в другой отдел.

Меню ⋮ → «Передать в другой отдел»

Выберите новый отдел (текущий отдел не показывается)

Выберите ответственного в новом отделе

Нажмите «Передать»

Вся история поверок сохраняется.

📸 [СКРИНШОТ 5.3] Модалка «Передача в другой отдел»
Что снять: модалку с текущим отделом (в шапке), выпадающими списками «Новый отдел» и «Ответственный».
Куда вставить: после списка выше.

5.4. История поверок
Меню ⋮ → «История поверок (N)» — в скобках количество записей

Откроется модалка с:

Карточкой прибора (модель, серийный, отдел, МПИ, статус)

Таймлайном поверок — свежие сверху

Кнопкой «Добавить поверку» — для ручного добавления записи

Кнопкой «Печать истории» — экспорт в Excel/PDF

📸 [СКРИНШОТ 5.4] Модалка «История поверок»
Что снять: таймлайн с 2–3 записями (даты, свидетельства, результаты с цветными бейджами).
Куда вставить: после абзаца выше.

5.5. Аудит изменений
Показывает, кто и когда менял прибор. Полезно, когда нужно выяснить, кто и когда изменил дату поверки.

Доступно только пользователям с правом «Аудит изменений».

📸 [СКРИНШОТ 5.5] Модалка «Аудит»
Что снять: список записей с датой, ФИО пользователя, действием и деталями изменений.
Куда вставить: после абзаца выше.

5.6. Отменить отправку
Показывается только для приборов на поверке. Возвращает прибор в статус «в работе».

Если прибор был отправлен с заменой — замена вернётся на склад.

📸 [СКРИНШОТ 5.6] Диалог «Отмена отправки»
Что снять: окно подтверждения с текстом «Отменить отправку P-001 на поверку? Замена P-005 вернётся на склад».
Куда вставить: после абзаца выше.

5.7. Удалить
Когда нельзя удалить:

Прибор на поверке — сначала оформите возврат или отмените отправку

Прибор используется как замена для другого — сначала верните оригинал с поверки

За прибором закреплена замена — сначала оформите возврат

Если удаление разрешено:

Меню ⋮ → «Удалить»

Подтвердите — действие необратимо

История поверок тоже удалится

📸 [СКРИНШОТ 5.7] Окно подтверждения удаления
Что снять: окно с текстом «Удалить оборудование P-001 вместе со всей историей поверок? Действие необратимо» и красной кнопкой «Удалить».
Куда вставить: после списка выше.

6. Добавление оборудования

Кнопка «Ещё ▼» в тулбаре → «Создать оборудование».

«Одна единица» — форма для одного прибора

«Партия (таблица)» — для массового добавления

📸 [СКРИНШОТ 6.1] Модалка создания с вкладками
Что снять: модалку с активной вкладкой «Одна единица» и видимыми вкладками сверху.
Куда вставить: после абзаца выше.

6.2. Одна единица
Заполните поля:

Внутренний номер — генерируется автоматически (можно оставить как есть)

Модель * — обязательное

Тип оборудования — Пипетка / Анализатор / Микроскоп и т.д.

Серийный номер

Производитель

Объём — для пипеток (мкл)

Отдел

Ответственный

Дата последней поверки * — обязательное

МПИ — межповерочный интервал (мес., по умолчанию 12)

Свидетельство — номер

Результат — Годен / Брак / В процессе

Статус — В работе / Не используется

Место хранения

Примечание

Поля с * — обязательные.

📸 [СКРИНШОТ 6.2] Форма добавления
Что снять: форму с заполненными полями (модель «Research Plus», тип «Пипетка», дата сегодня, объём 1000 и т.д.).
Куда вставить: после списка выше.

6.3. Партия (таблица)
Для массового добавления похожих приборов:

Вкладка «Партия (таблица)»

Нажмите «Добавить строку» — появится пустая строка

Заполните ячейки (как в Excel)

Добавьте нужное количество строк (максимум — по настройкам админа)

Нажмите «Создать N единиц»

При >20 строк появится подтверждение.

📸 [СКРИНШОТ 6.3] Вкладка «Партия»
Что снять: таблицу с 3–4 заполненными строками, кнопкой «Добавить строку» сверху и «Создать N единиц» внизу.
Куда вставить: после списка выше.

6.4. Штрихкод
В форме есть поле «Штрихкод»:

Автоматически — генерируется из инв. номера, серийного или ID

Вручную — админ может ввести своё значение

Сброс — кнопка «↺» возвращает к авто

Длина штрихкода ограничена настройкой админа (стандарт — 255 символов).

16. Частые проблемы
«Нет прав на действие»
Обратитесь к администратору — у вашей роли нет нужного права.

«Сессия истекла»
Нажмите OK — система вернёт вас на экран входа. Войдите заново. Если это происходит часто — возможно, администратор снизил время сессии.

«Прибор заблокирован»
Другой пользователь открыл прибор на редактирование. Подождите 30 минут (блокировка снимется автоматически) или обратитесь к этому пользователю.

«Не удалось сохранить»
Возможно, кто-то изменил данные параллельно. Ваши изменения сохранятся как черновик — при следующем открытии они подставятся в форму.

«Сервис временно недоступен»
Сервер перегружен или обновляется. Подождите 10–20 секунд и повторите.

«Ошибка 500»
Обратитесь к администратору. Он посмотрит логи и разберётся.

Белый экран / «что-то пошло не так»
Обновите страницу (Ctrl+F5)

Если не помогло — очистите кеш браузера

Если всё ещё белый — обратитесь к админу

1. Введение
1.1. Кому это руководство
Администратор — пользователь с ролью admin (встроенной или кастомной, но с флагом is_admin = true). Администратор имеет полный доступ ко всем функциям системы, включая:

Управление пользователями и ролями

Настройка полей формы, отделов, типов оборудования

Настройка политики паролей

Управление принтерами и штрихкодами

Просмотр журналов (аудит + ошибки)

Сброс данных

1.2. Принципы безопасности
Администратор видит всё, но есть встроенные защиты:

Нельзя удалить встроенного admin

Нельзя понизить последнего администратора

Нельзя удалить себя из системы

Логин admin нельзя менять

Критичные настройки (пароли, impersonation) — только для админов

1.3. Что нельзя делать никому (даже админу)
Изменить системные роли (user, senior_lab, admin)

Удалить последнего админа

Восстановить удалённые данные без бэкапа

2.1. Установка пароля администратора

Откройте экран входа

Введите логин admin, поле «Пароль» оставьте пустым

Нажмите «Войти»

Система попросит установить пароль

Введите новый пароль (соответствующий политике) → «Установить»

11. Частые проблемы
«Не могу удалить отдел»
Отдел используется приборами. Переведите их в другой отдел, потом удаляйте.

«Не могу удалить тип оборудования»
Тип используется приборами. Смените им тип, потом удаляйте.

«Логин администратора менять нельзя»
Это защита встроенного admin — чтобы никто случайно не потерял доступ к системе.

«Принтер не отвечает»
Проверьте IP/порт (⋮ → Проверить связь)

Проверьте, включён ли принтер

Проверьте сеть (ping)

Если не критично — настройте Fallback на PDF (файл будет скачиваться вместо отправки)

«Импорт не распознаёт колонки»
Проверьте заголовки — должны совпадать со стандартными. Полный список — в import.js::HEADER_MAP.

Где смотреть логи
bash
docker logs pipette_new_app --tail 100
docker logs pipette_new_db --tail 50
Как сбросить пароль админа (если потерян)
Через БД:

sql
UPDATE users SET password = '', must_set_password = 1 WHERE login = 'admin';
После этого войти под admin с пустым паролем — система попросит установить новый.

1. Общая информация
1.1. Базовый URL
text
https://<адрес-сервера>/api
1.2. Формат данных
Запрос: Content-Type: application/json

Ответ: всегда JSON

Кодировка: UTF-8

1.3. Авторизация
Все защищённые эндпоинты требуют JWT-токен в заголовке:

text
Authorization: Bearer <токен>
Как получить токен: POST /auth/login (см. раздел 2.1).

Срок жизни токена: 24 часа. По истечении — 401 Unauthorized, нужно логиниться заново.

1.4. Коды ответов
Код	Значение	Когда
200 OK	Успех	GET, PUT
201 Created	Создано	POST
400 Bad Request	Неверные данные	Валидация не пройдена
401 Unauthorized	Нет токена / истёк / неверные креды	—
403 Forbidden	Нет прав / требуется смена пароля	—
404 Not Found	Объект не существует	—
409 Conflict	Конфликт (дубль, race, draft)	—
422 Unprocessable Entity	Семантическая ошибка	—
429 Too Many Requests	Rate limit	Nginx: 30/мин на /auth/login
500 Internal Server Error	Ошибка сервера	Смотреть app_logs
503 Service Unavailable	Сервис недоступен	Сбой роль-кеша, БД
1.5. Формат ошибок
Стандартный:

json
{ "error": "Текст для пользователя" }
Расширенный:

json
{
  "error": "Текст",
  "code": "машинный_код",
  "details": { ... },
  "affected": 5
}
Коды ошибок — см. раздел 13.

1.6. Пагинация
Все списочные эндпоинты поддерживают:

page — номер страницы (с 1)

limit — размер (макс. 500)

sort — поле сортировки

dir — asc / desc

search — поиск

filters — JSON-строка с фильтрами

Пример:

text
GET /pipettes/paged?page=2&limit=50&sort=id&dir=asc&search=Research
2. Аутентификация (/auth)
2.1. POST /auth/login — вход
Права: публичный
Rate limit: 30 запросов/минуту с одного IP

Тело:

json
{
  "login": "admin",
  "password": "Secret123!"
}
Особый случай — первый вход admin:
Если must_set_password = 1, пароль должен быть пустым ("" или не передан). Иначе — 401.

Ответ 200:

json
{
  "token": "eyJhbGc...",
  "user": {
    "id": "admin1",
    "login": "admin",
    "fullName": "Администратор",
    "position": "Администратор системы",
    "role": "admin",
    "isAdmin": true,
    "roleName": "Администратор",
    "permissions": ["*"],
    "onlyOwnDepartment": false,
    "isActing": false,
    "mustChangePassword": false,
    "mustSetPassword": false
  }
}
Ошибки:

Код	Текст
400	«Заполните поле «Логин»»
400	«Заполните поле «Пароль»»
401	«Неверный логин или пароль»
401	«Пароль ещё не установлен. Оставьте поле пустым.»
429	«Слишком много запросов»
2.2. GET /auth/verify — проверка сессии
Права: требуется токен (исключение: allowWhenPasswordMustChange)

Ответ 200:

json
{ "user": { ... } }
(структура user — как в /login)

Особенность: если must_change_password = 1 — этот эндпоинт всё равно работает (чтобы фронт мог показать модалку смены пароля). Все остальные защищённые эндпоинты в это время возвращают 403 password_change_required.

2.3. GET /auth/password-policy — политика паролей
Права: требуется токен

Ответ 200:

json
{
  "minLength": 8,
  "maxLength": 64,
  "requireLower": true,
  "requireUpper": true,
  "requireDigit": true,
  "requireSpecial": true,
  "forbidSpaces": true
}
2.4. POST /auth/change-password — смена пароля
Права: требуется токен

Тело:

json
{
  "currentPassword": "Old123!",
  "newPassword": "New456!",
  "confirmPassword": "New456!"
}
Ответ 200:

json
{
  "message": "Пароль изменён",
  "token": "eyJhbGc..."
}
Важно: старый токен инвалидируется. Используйте новый token из ответа.

Ошибки:

400 — «Текущий пароль неверен»

400 — «Новый пароль должен отличаться от текущего»

400 — «Пароль не соответствует требованиям:\n• Минимум 8 символов\n• ...»

2.5. POST /auth/setup-password — установка пароля (первый вход)
Права: требуется токен, must_set_password = 1

Тело:

json
{
  "newPassword": "First123!",
  "confirmPassword": "First123!"
}
Ответ 200:

json
{
  "message": "Пароль установлен",
  "token": "eyJhbGc..."
}
Ошибка 400 — если пароль уже установлен.

2.6. POST /auth/impersonate/:userId — вход под другим
Права: _isAdmin + режим impersonation_mode (не off)

Ответ 200:

json
{
  "token": "eyJhbGc...",
  "user": { ... }
}
В токене добавлены impersonatedBy, impersonatedByName.

Ошибки:

403 — «Вход под пользователем отключён»

403 — «Только встроенный админ может входить под другими» (при mode = admin)

400 — «Вы уже вошли под этой учётной записью»

404 — «Пользователь не найден»

2.7. POST /auth/stop-impersonate — возврат к своей учётке
Права: требуется токен + impersonatedBy в токене

Ответ 200:

json
{ "message": "Возврат залогирован" }
Особый случай: если админ, под которым вы работали, был удалён — возвращается:

json
{ "message": "Возврат залогирован (админ удалён)", "forceLogout": true }
Фронт должен сделать logout и перекинуть на /login.

Права: публичный

2.1. server.js — точка входа
Что делает:

Загружает .env

Подключает errorLogger (для 403/409)

Подключает errorHandler (для 500)

Монтирует все роуты:

SPA-fallback: всё, что не /api/* и не /help-defaults/* → отдаёт frontend/index.html

3.2. api/ — обёртки над fetch
Все API-вызовы идут через apiRequest() из api/client.ts.

api/client.ts — это сердце API-слоя:

Базовый URL: /api

Обрабатывает:

ApiError — класс с status, code, response

5. Куда смотреть при багах
5.1. Типовые баги и где искать
Симптом	Куда смотреть
«Нет прав» на действие	middleware/auth.js::requirePermission → routes/*.js (проверка прав) → pipettes/index.js (требуемые права)
Статус прибора неверный	routes/pipettes/_helpers.js::sqlComputedStatus (единственный источник)
Прибор не удаляется	routes/pipettes/crud.js::DELETE (проверки sent, replacing, replaced_by)
Не работает смена типа (ID не меняется)	_helpers.js::maybeRegenerateId — проверка префикса
Штрихкод не обрезается	_helpers.js::getBarcodeMaxLen + routes/barcodes.js::resolveBarcodeValue + инвалидация кеша в settings.js
Кеш не обновляется	routes/settings.js::PUT /system — блок инвалидации в конце
Двойной refreshUser	api/client.ts::_refreshing
Модалка не ресайзится	_modals.css — .modal-settings-resizable + SettingsModal.vue
Force reload не работает	views/MainView.vue::onForceReload + ChangePasswordModal.vue (dispatchEvent)
PDF/Excel пустые	routes/export.js (режим) + useExport.ts (фронт)
Импорт пропускает всё	routes/import.js::HEADER_MAP (проверка заголовков) + mapHeader
Не работает поиск	_helpers.js::buildFiltersWhere (search_text LIKE) + search_text в generated column
Права в шапке неверные	AppHeader.vue::positionLine + utils/roles.js::getRoleDef (кеш)
Impersonation не сохраняет	routes/auth.js::impersonate (проверка mode) + api/client.ts (сохранение токена)
«Заблокировано пользователем X»	routes/pipettes/locks.js (проверка edit_locks) + useFormModals.ts::deleteConfirm

6. Потоки данных
6.1. Вход
text
LoginView → authStore.login() → POST /auth/login
→ JWT → sessionStorage('pipette_session')
→ клиент → AuthStore.user
6.2. Загрузка таблицы
text
MainView.onMounted → settingsStore.loadAll() + prefsStore.load()
→ pipettesStore.loadPaged() (GET /pipettes/paged)
→ items[] + counters
6.3. Редактирование (с локом)
text
PipetteFormModal.openForm
→ GET /pipettes/:id/lock (проверка)
→ POST /pipettes/:id/lock (захват)
→ heartbeat каждые 3 сек (GET /:id/lock)
→ PUT /pipettes/:id (сохранение)
→ DELETE /:id/lock (освобождение)
Если лок захвачен другим — heartbeat получает mine: false → автосохранение в draft + закрытие + предупреждение.

6.4. Отправка на поверку
text
Toolbar «Отправить (N)» → useBulkModals.openBulkSend
→ BulkSendModal.open
→ POST /pipettes/bulk-lock (захват локов)
→ POST /pipettes/available-for-replacement-batch (для замен)
→ POST /pipettes/bulk-send
→ pip.loadPaged + stats.load
6.5. Смена пароля (force)
text
Login → mustChangePassword → ui.open('changePassword')
→ ChangePasswordModal.onSubmit
→ POST /auth/change-password → новый токен
→ auth.applySession + refreshUser
→ window.dispatchEvent('force:reload')
→ MainView.onForceReload → loadAllData
Почему так: без force:reload таблица была бы пустой (все запросы блокировались бы 403).

🛠️ Шаг 2: Инструменты конвертации
Есть 3 варианта. Выбери тот, что удобнее.

Вариант A — Pandoc (рекомендую, кроссплатформенно)
Установка:

Windows: pandoc.org/installing + MiKTeX (для PDF) или wkhtmltopdf

macOS: brew install pandoc

Linux: sudo apt install pandoc

Конвертация MD → DOCX:

bash
pandoc user-guide.md -o user-guide.docx \
  --reference-doc=template.docx \
  --toc --toc-depth=2 \
  --resource-path=.:screenshots
template.docx — шаблон с настройками стилей (шрифт, отступы, колонтитулы). Можешь создать в Word: «Сохранить как → Шаблон Word (*.dotx)».

Конвертация MD → PDF:

bash
pandoc user-guide.md -o user-guide.pdf \
  --pdf-engine=xelatex \
  -V mainfont="DejaVu Sans" \
  -V geometry:a4paper \
  -V geometry:margin=2cm \
  --toc --toc-depth=2 \
  --resource-path=.:screenshots \
  -V lang=ru
Почему xelatex + DejaVu Sans: поддерживает кириллицу. pdflatex её ломает.

Вариант B — VS Code + Markdown PDF (проще, но меньше контроля)

Для Word — расширение «Markdown Preview Enhanced» → Export to DOCX

Плюс: без установки pandoc. Минус: меньше контроля над стилями.

Вариант C — Онлайн
md2pdf.netlify.app — MD → PDF

cloudconvert.com — MD → DOCX

dillinger.io — MD → HTML → печать в PDF

🔧 Шаг 4: Подготовка Markdown к конвертации
Сейчас Markdown в чате — с метками 📸 [СКРИНШОТ X.X]. Перед сборкой их нужно превратить в реальные картинки.

Замени метки на ссылки
Было:

markdown
> **📸 [СКРИНШОТ 2.1] Экран входа**
> **Что снять:** весь экран логина...
> **Куда вставить:** после этого абзаца.
Стало (после того как снял скриншот):

markdown
![Экран входа](screenshots/02-01-login.png)
*Рисунок 2.1 — Экран входа в систему*
Если скриншота пока нет — оставь заглушку:

markdown
> 🖼️ **Скриншот 2.1 — Экран входа** *(снять: весь экран логина)*
Pandoc отрендерит её как blockquote с иконкой.

Обнови внутренние ссылки
В оглавлении:

markdown
- [Вход в систему](#2-вход-в-систему)
Pandoc автоматически сгенерирует оглавление через --toc. Ручное оглавление можно убрать (или оставить для GitHub).

Убери служебные пометки
Из документов нужно убрать:

**Права:** — в руководстве пользователя (там это «🛡 Требуется вход»)

**Возвращает:** — если писал для API (лучше сформулировать «Ответ:»)

Мета-комментарии типа «что снять», «куда вставить» — после вставки скриншотов
