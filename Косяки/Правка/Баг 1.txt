BUG-2025-001: POST /api/pipettes → 500 при параллельном создании с одним ID
────────────────────────────────────────────────────────────────────────
Серьёзность: 🟢 Низкая (не критично)
Приоритет:   Низкий
Компонент:   routes/pipettes.js — роут POST /
Обнаружен:   автотест блок 22.2 (KDL TEST SUITE v2.1)

ОПИСАНИЕ
────────
При одновременной отправке 8+ POST /api/pipettes с одним и тем же ID
часть запросов (5 из 8 в тесте) получает HTTP 500 с телом
{ error: 'Ошибка создания оборудования' }.

Ожидаемое: 409 Conflict с понятным текстом.
Фактическое: 500 Internal Server Error.

ВОСПРОИЗВЕДЕНИЕ
───────────────
1. Войти как admin
2. F12 → Console
3. Запустить 8 параллельных POST с одним и тем же id

Код для воспроизведения — в файле test_22_race.html / в v2.2 скрипта.

ПРИЧИНА (гипотеза)
──────────────────
1. Запросы 1–5 проходят SELECT id FROM pipettes WHERE id = ? — БД пуста
2. Все идут на INSERT — MySQL блокирует по PRIMARY KEY
3. Одна проходит (201), остальные получают ER_DUP_ENTRY
   или ER_LOCK_WAIT_TIMEOUT / ER_LOCK_DEADLOCK
4. В catch срабатывает проверка RACE_CODES (см. ниже) —
   но НЕ ловит реальный код ошибки, поэтому → 500
5. Запросы 7–8 видят существующий ID на SELECT → 409 ID уже существует

ПОСЛЕДСТВИЯ
───────────
✅ Данные НЕ теряются — транзакция откатывается
✅ БД НЕ портится — PRIMARY KEY блокирует дубликат
✅ Один запрос успешно создаёт пипетку
❌ Пользователь получает 500 вместо 409
❌ Логи засоряются ложными ошибками
❌ Мониторинг может видеть ложные алерты

ЧАСТОТА ПРОЯВЛЕНИЯ
──────────────────
Реальная жизнь: практически никогда
- 1 пользователь, 2 клика подряд → 409 (SELECT успевает увидеть)
- 2 пользователя одновременно → почти всегда 409
- 8 параллельных запросов → только в стресс-тесте

ПАТЧ (когда будем фиксить)
──────────────────────────
Файл: routes/pipettes.js — catch в роуте POST /
Что: расширить RACE_CODES + использовать errno MySQL

const isRace =
  RACE_CODES.has(e.code) ||
  /Duplicate entry|Deadlock|lock wait timeout/i.test(e.message || '') ||
  [1062, 1205, 1213].includes(e.errno);  // 🆕 errno MySQL

ЧТО НУЖНО ДЛЯ ТОЧНОГО ПАТЧА
───────────────────────────
1. Включить логи NSSM:
     nssm set pipette_app AppStderr C:\pipette_logs\err.log
2. Запустить тест
3. Прочитать C:\pipette_logs\err.log
4. Найти точный e.code / e.errno / e.message

ПРИЧИНА ОТЛОЖЕННОСТИ
────────────────────
- Не критично — данные целые
- Проявляется только при искусственной гонке
- Дешёвый фикс — 2 строки — сделаем при первой возможности
- Сейчас важнее покрыть блоки 21–43
