🔴 Блок 1. Backend — защита от невалидного JSON
1.1. POST /api/pipettes с телом null → 400
Как проверить: F12 → Console

js
const t = JSON.parse(sessionStorage.getItem('pipette_session')).token;
const r = await fetch('/api/pipettes', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer ' + t, 'Content-Type': 'application/json' },
  body: 'null'
});
console.log('Статус:', r.status, await r.text());
Ожидаемо: Статус: 400 {"error":"Тело запроса должно быть JSON-объектом"} или похожее.

1.2. POST с телом not-json → 400
js
const r = await fetch('/api/pipettes', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer ' + t, 'Content-Type': 'application/json' },
  body: 'not-json'
});
console.log(r.status, await r.text());
Ожидаемо: 400 + {"error":"Некорректный JSON в теле запроса"}.

1.3. Сервер жив после мусорных запросов
js
const r = await fetch('/api/pipettes', {
  headers: { 'Authorization': 'Bearer ' + t }
});
console.log('GET после тестов:', r.status);
Ожидаемо: 200. Не 502/504.

1.4. В БД не добавилось мусорных записей
js
const list = await apiRequest('/pipettes', 'GET');
console.log('Всего пипеток:', list.length);
Запомни число до тестов и после — должно совпадать.

Если всё ✅ — блок закрыт.

🔴 Блок 2. Backend — CRUD и связи
2.1. POST с кастомным полем → custom_data
js
const p = await apiRequest('/pipettes', 'POST', {
  model: 'TEST-CHECK',
  equipmentType: 'pipette',
  department: 'Гематологический отдел',
  lastCalibration: '2025-09-24',
  interval: 12,
  responsible: 'Администратор',
  inventorynumber: 'INV-CHECK-001'
});
console.log('Создано:', p.id);
const got = await apiRequest('/pipettes/' + p.id, 'GET');
console.log('custom_data:', got.custom_data);
Ожидаемо: custom_data.inventorynumber === 'INV-CHECK-001'. Системные поля — в колонках, не в custom_data.

2.2. PUT с кастомным полем — мёрж, не затирание
js
await apiRequest('/pipettes/' + p.id, 'PUT', { calibration_place: 'Лаб. 999' });
const after = await apiRequest('/pipettes/' + p.id, 'GET');
console.log('custom_data:', after.custom_data);
Ожидаемо: оба поля (inventorynumber и calibration_place) в custom_data.

2.3. PUT с interval='' → NULL
js
await apiRequest('/pipettes/' + p.id, 'PUT', { interval: 12 });
await apiRequest('/pipettes/' + p.id, 'PUT', { interval: '' });
const got = await apiRequest('/pipettes/' + p.id, 'GET');
console.log('interval:', got.interval, '(тип:', typeof got.interval + ')');
Ожидаемо: null.

2.4. PUT с lastCalibration='' → дата НЕ обнуляется
js
const before = await apiRequest('/pipettes/' + p.id, 'GET');
await apiRequest('/pipettes/' + p.id, 'PUT', { lastCalibration: '' });
const after = await apiRequest('/pipettes/' + p.id, 'GET');
console.log('Дата до:', before.last_calibration);
console.log('Дата после:', after.last_calibration);
Ожидаемо: дата не изменилась.

2.5. DELETE пипетки без связей → 200
js
await apiRequest('/pipettes/' + p.id, 'DELETE');
console.log('Удалено');
2.6. DELETE несуществующего → 404
js
try {
  await apiRequest('/pipettes/P-99999', 'DELETE');
} catch (e) {
  console.log('Ошибка:', e.message);
}
Ожидаемо: ошибка с «не найдена» / 404.

Если всё ✅ — блок закрыт.
